# Typle Audit — 2026-11-18

Audit of `typle` v0.4.0 (Elixir 1.20.4 / OTP 29). All findings verified by
execution against the working tree, not by inspection alone.

Baseline measured at audit time:

- `mix test` → 177 passed (2 doctests, 175 tests)
- `mix credo --strict` → 439 mods/funs, found no issues
- `mix dialyzer` → Total errors: 0

---

## 1. Strong parts

*The regression suite is the project's real backbone.* `test/typle/regression_test.exs`
is not decorative — each test names the exact AST shape that broke and asserts the
invariant that broke with it. The struct-update test pins
`{:%{}, _, [{:|, _, [struct, [key: value]]}]}` and asserts `infer_file/1` returns
`{:ok, ...}` rather than raising; the `with`/`for` tests assert
`Macro.to_string(expanded)` is a binary, which is the *only* assertion that catches
body-splicing bugs, since spliced AST is still a tuple.

*The `:standard_error` concurrency fix is genuinely well-engineered.*
`lib/typle/inference/expander.ex:69-83` replaced a global
`Process.whereis(:standard_error)` swap with `Code.with_diagnostics([log: false], ...)`
**inside the task**, with a comment explaining that the global swap "would race with
other callers and could leave the VM without an error device." The invariant is then
*proven*, not assumed: `test/typle/inference/expander_test.exs` runs 32 concurrent
`expand_file` + `infer_file` calls at `max_concurrency: 8` and asserts
`Process.whereis(:standard_error)` is unchanged before, during, and after every one.

*The `dynamic?` flag is a disciplined type boundary.* Rather than inventing an
`:unknown` kind that every `case` would have to handle, `Typle.Type` carries
unknown-ness as a boolean orthogonal to `kind` (`lib/typle/type.ex:38`). This is why
`Pattern.narrow/2` (`lib/typle/inference/pattern.ex:158-166`) can strip the wrapper,
narrow the inner type structurally, and re-wrap — and why
`test/typle/inference/pattern_test.exs` can assert
`%{num: %Type{kind: :integer, dynamic?: true}}` for exactly what `Integer.parse/1`
returns.

*Version-drift is absorbed at one boundary.* `lib/typle/beam.ex:151-153` normalises
`elixir_checker_v7` (map exports) and `v8` (list exports) to a single shape via
`normalise_exports/1`, and `@supported_versions` is a module attribute, so adding v9
is a one-line change.

*Quality gates are wired, not aspirational.* `mix quality` and `mix quality.ci`
(`mix.exs:48-51`) chain `format`, `credo --strict`, `dialyzer`;
`.github/workflows/ci.yml` runs them as a separate `lint` job with a PLT cache and
gates on a `quality` job.

## 2. Weaknesses & glitches to fix

### Defect 1 (worst) — one malformed construct destroys inference for the entire file

`lib/typle/inference/expr.ex:119` destructures each `case` clause as
`{:->, _, [[pattern | guards], body]}`. An empty `case` expands to
`{:__block__, _, []}`, which is not a list, so `Enum.reduce` raises
`Protocol.UndefinedError`:

```
lib/typle/inference/expr.ex:119: Typle.Inference.Expr.infer/2
lib/typle/inference.ex:167: Typle.Inference.walk_definition/2
lib/typle/inference.ex:38: Typle.Inference.infer_file/2
```

`infer_file/2` (`lib/typle/inference.ex:34-42`) has **no** `try/rescue`, so a single
empty `case` or `cond` in a 4000-line file makes `mix typle`, `mix typle.dump`, and
every Credo check calling `Typle.type_at/3` fail with a stack trace and *zero*
results. Verified with a good function and an empty `case` in the same file — the
whole file aborted.

**Fix:** wrap the body of `infer_file/2` in `try/rescue` returning partial results,
and add a fallback clause to the `Enum.reduce` in `infer/2`.

### Defect 2 — `Type.union([])` produces an invalid type rendering as the empty string

`lib/typle/type.ex:126-140`: `union/1` has a `[single]` clause and a general clause,
but `[]` falls into the general clause, producing `%Type{kind: :union, params: []}`.
Verified: `Typle.Type.to_string(Typle.Type.union([]))` returns `""`, and `inspect`
returns `#Typle.Type<>`. Reachable from `Expr.infer/2`'s `cond` clause
(`expr.ex:172`), which calls `Type.union(Enum.reverse(branch_types))` with no empty
guard.

**Fix:** add `def union([]), do: none()` before the general clause.

### Defect 3 — `mix typle` and `mix typle.dump` exit 0 on every failure

`lib/mix/tasks/typle.ex:80-82` and `lib/mix/tasks/typle.dump.ex:52` call
`Mix.shell().error(...)` but never exit non-zero. Verified:
`mix typle /tmp/nope.ex:1:1; echo $?` → `Error: :enoent`, `exit=0`. Makes the task
unusable in CI.

**Fix:** `Mix.raise/1` instead of `Mix.shell().error/1`.

### Defect 4 — `--format` is unvalidated and raises `FunctionClauseError`

`lib/mix/tasks/typle.ex:74-82` has clauses only for `"text"` and `"json"`. Verified:
`--format yaml` on a valid position raises
`defp output_result(+{:ok, %{type: type, expr: expr}}+, +file+, +line+, +col+, -"json"-)`.

**Fix:** validate `format in ["text", "json"]` in `run/1` and `Mix.raise` with the
accepted values. Same applies to `typle.dump.ex:38`.

### Defect 5 — anonymous function bodies are never inferred

`lib/typle/inference/expr.ex:238-241` ignores `_clauses` entirely and returns
`%Type{kind: :function, params: []}`. Verified on `fn x -> x + 1 end`: the only
recorded type is `#Typle.Type<>` at the `fn` node; the parameter `x` and body
`x + 1` are never visited. Since `Enum.map(list, fn item -> ... end)` is the single
most common Elixir idiom, this is a large blind spot.

**Fix:** iterate `clauses`, `Pattern.infer/2` each parameter against
`Type.dynamic()`, push a scope, `infer/2` the body, return
`Type.function([{arg_types, body_type}])`.

### Defect 6 — same-file private calls always resolve to `dynamic()`

`lib/typle/inference/expr.ex:296-300`: a local call with `env.module` set goes to
`SignatureStore.return_type(mod, fun, arity, ...)`, which looks up the *compiled*
beam. For a module that isn't compiled yet, the lookup misses. Verified on
`def a(x), do: b(x)` / `defp b(y), do: y + 1`: `b/1` in the store is `dynamic()`, and
the call site is `dynamic()`, even though `b`'s body inferred
`float() or integer()`.

**Fix:** accumulate inferred return types into `Env` and consult that map in the
local-call clause before hitting `SignatureStore`.

### Defect 7 — `with`'s `else` and `try`'s `rescue`/`catch`/`after` branches are dropped

`lib/typle/inference/expr.ex:216` reads only `Keyword.get(body_kw, :do)`, and
`:242-247` reads only `blocks[:do]`. Verified: a `with ... else _ -> :boom end`
records no `:boom`; a `try ... rescue e -> :rescued end` records no `:rescued`. This
under-reports types at exactly the error paths a type query is most useful for.

**Fix:** infer the `:else`/`:rescue`/`:catch` bodies and `Type.union` them into the
result.

### Smell 1 — `SignatureStore.load_project/1` is unbounded and atom-leaking

`lib/typle/signature_store.ex:36-52` wildcards `**/*.beam` across the whole build
path — measured **4416 rows** loaded — and `load_beam_file/1` (`:100`) calls
`String.to_atom/1` on every basename, creating atoms that are never garbage-collected.
Also returns `{:ok, 0}` for a nonexistent path, indistinguishable from success.

**Fix:** restrict to `Mix.Project.compile_path()`; use the module name returned by
`Beam.read_signatures/1` where available.

### Smell 2 — `Pattern.extract_tuple_element/2` is public without a reason

`lib/typle/inference/pattern.ex:236` is `def` (not `defp`) marked `@doc false`;
`__info__(:functions)` confirms it is exported. Internal helper leaking into API
surface.

**Fix:** make it `defp`.

### Smell 3 — CI never tests the version the project actually runs on

`.github/workflows/ci.yml:19-24` pins `elixir: '1.20.0-rc.4'` with OTP `27` and
`28`. The local toolchain is Elixir **1.20.4** / OTP **29**, and the entire
`elixir_checker_v8` code path exists *because* 1.20.4 changed the format. The v8
regression test passes locally but CI's matrix would exercise v7 only.

**Fix:** add `1.20.4`/OTP 29 to the matrix.

### Smell 4 — `CHANGELOG.md` has the header duplicated

Lines 1-6 repeat `# Changelog` and the "All notable changes" sentence twice.

**Fix:** delete lines 4-6.

### Taste — `Inference.infer_file/2` accepts `:unstable` but returns a different shape

`lib/typle/inference.ex:35-37` returns `Unstable.types_for_file(file)`, a bare type
map, while the stable path returns `%{types:, exprs:}`. The recursion terminates only
because `Unstable` falls back to `infer_file/2` *without* the flag. Fine as-is, but
the `:unstable` option on `Inference` is redundant with `Typle`'s own flag.

## 3. Codebase improvement ideas

Ordered by value-for-effort.

1. **File-level rescue in `infer_file/2`** (~10 lines). Converts every current and
   future `Expr.infer/2` crash from "whole file fails" to "that expression is
   `dynamic()`". The fallback clause `def infer(_other, env)` at `expr.ex:330`
   already exists — the problem is only that some clauses raise *before* reaching it.
2. **`union([])` / `intersection([])` guards in `Typle.Type`** (~4 lines), plus
   doctests so `test/typle/type_test.exs`'s `doctest Typle.Type` picks them up.
3. **Test the untested source files.** `lib/typle/expr_map.ex` (58 lines),
   `lib/typle/unstable/type_capture.ex` (37 lines), `lib/typle/diagnostic.ex`
   (104 lines). `ExprMap.extract/1` verified to return `"add(a, b)"` for `{6, 7}` of
   the sample fixture; `TypeCapture` is an ETS wrapper with four obvious assertions;
   `Diagnostic.capture/1` verified to return `{:ok, []}` on a clean file.
4. **Property-based tests for `Typle.Type`** (see Phase 1 below).
5. **Extract duplicated `type_diagnostic?/1` message check** in
   `lib/typle/diagnostic.ex:79-96` — two clauses differing only in
   `IO.chardata_to_string/1`.
6. **Document handled AST forms** at the top of `Expr.infer/2`, making the
   `fn`/`with`/`try` gaps visible at a glance.

---

## 4. UX improvement ideas

Ordered by value-for-effort.

1. **Exit non-zero on failure** (Defect 3). Returning 0 after `Error: :enoent` means
   "type check passed" to every CI script.
2. **Replace raw Elixir terms with sentences.** Verified outputs: `Error: :enoent`,
   `Error: {:module_not_available, NoSuchModule}`, `Error: :no_type_at_position`.
   Map known atoms to messages naming the file, and for
   `{:module_not_available, m}` suggest `mix compile`.
3. **Validate `--format`** and list valid values (Defect 4).
4. **Make "no types on this line" a next step, not silence.**
   `output_line_results/3` (`typle.ex:84-93`) `Enum.each`es an empty list and prints
   nothing. Suggest the nearest lines that do have types — the data is already in
   `type_map`.
5. **Surface partial-inference failures** — after Defect 1's rescue, report how many
   expressions were skipped and where.
6. **Unify argument grammar** between `mix typle` and `mix typle.dump`.
   `typle.dump.ex:44-50` branches on `.ex` suffix, so `mix typle.dump lib/foo.ex:15`
   reports `:enoent`. Share `parse_location/1`.
7. **Add a "Known blind spots" README subsection** listing `fn` bodies, same-file
   private calls, and `with`/`try` non-`do` branches.
8. **Name the checker version in the error.** `{:unsupported_checker_version, v}`
   currently renders as an opaque tuple; special-case it to name the version and the
   supported set.

Two defects were found *while fixing* D7, both discovered by the new tests:

- `with`/`try` bodies are **lists of `->` clauses**, not single expressions.
  Routing them through `infer/2` matched the generic list clause and produced
  `list(dynamic())`, silently discarding every branch. Added `infer_clauses/2`.
- `Diagnostic.capture/1` had **never worked**: `ParallelCompiler.compile/2`
  returns warnings as a *map* (`%{compile_warnings: ..., runtime_warnings: ...}`),
  so `errors ++ warnings` raised and `Enum.filter(map, ...)` failed. Added
  `diagnostics_list/1`.

### Phase 2 — Codebase improvements (done)

- Tests for the three previously untested modules:
  `test/typle/expr_map_test.exs`, `test/typle/diagnostic_test.exs`,
  `test/typle/unstable/type_capture_test.exs`.
- `test/typle/type_properties_test.exs` — 13 `ExUnitProperties` properties
  covering union commutativity/associativity/idempotence, non-empty rendering,
  and `dynamic/1` idempotence. Added `stream_data ~> 1.1` (test only).
- The property suite immediately found a real defect: `open_tuple([])` rendered
  as `"{, ...}"`. Fixed with an explicit `format_kind(:tuple, {:open, []})`
  clause plus a `never renders a dangling separator` property.
- `type_diagnostic?/1`'s two near-identical clauses collapsed into one, with
  markers in a module attribute.

### Phase 3 — UX improvements (done)

- Non-zero exit on every failure path.
- Raw terms replaced with sentences naming the file and the next step
  (`No such file: lib/a.ex`, `Run `mix compile` first`, ...).
- `--format` validated, listing valid values.
- Empty line queries suggest the nearest lines that *do* have types.
- Skipped forms reported: `Note: N top-level form(s) could not be inferred ...`
  in text, a `skipped` array in JSON, and
  `Typle.types_for_file_with_skipped/2` for programmatic use.
- `mix typle.dump` accepts `file:line` via the shared `Support.parse_location/1`.
- README gains a "Known blind spots" section.

### Defects found during the work (not in the original audit)

1. **`Diagnostic.capture/1` had never worked.** `ParallelCompiler.compile/2`
   returns warnings as a map, so `errors ++ warnings` raised and
   `Enum.filter(map, ...)` failed. Found by the new `diagnostic_test.exs`.
2. **`open_tuple([])` rendered as `"{, ...}"`.** Found by the new property
   suite's non-empty-rendering property.
3. **`with`/`try` clause lists were inferred as `list(dynamic())`.** Found while
   writing the D7 regression tests; fixed with `infer_clauses/2`.

Each is now covered by a test that fails without the fix.
